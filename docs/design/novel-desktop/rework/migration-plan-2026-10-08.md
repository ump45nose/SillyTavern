# 页面尺寸校准与迁移方案（2026-10-08）

状态：用户已授权执行，运行时代码已接入并按本方案复查；见 [接入记录](migration-implementation-2026-10-08.md)。沿用已确认的纸张阅读、输入底栏、五类资源编辑风格。下文保留已确认要求，不改写旧设计稿来迁就实现。

## 先校准尺寸

用户提供的完整内容区截图为 2992×1634 图像像素。已知运行时顶栏 74 CSS px、左栏 260 CSS px，与截图中的约 148、520 图像像素相符；因此主确认尺寸暂定为 **1496×817 CSS px，截图有效像素比例约 2**。这是根据已知尺寸的推断，不能据此判断浏览器缩放是否为 100%，也不能把 2992 当作 CSS 布局宽度。

先前偏差有三个来源：对话预览容器与浏览器工作区尺寸不同；双列表单在宽窗口里直接拉伸；原有组件的局部操作被抽离并集中到页首。尺寸校准解决前两项，组件迁移方式解决第三项。功能与溢出检查不能代替逐页视觉验收。

| 规则 | 此次约定 |
|---|---|
| 主确认窗口 | 1496×817 CSS px；生成同尺寸、有效像素比例 2 的检查图 |
| 其他桌面检查 | 1366×768、1440×900、1920×1080 |
| 公共顶栏 | 74px |
| 首页左栏 | 260px；1400px 以下沿用 240px |
| 首页右编辑栏 | 保持 460px；1400px 以下沿用 440px |
| 一级资源列 | 右栏左侧外展 180px，不扣减右编辑栏宽度 |
| 阅读区 | 扣除已打开栏位后真实排版，不缩放整页；保留左右收纳控制 |
| 独立设置导航 | 沿用 162px，表单区用实际剩余宽度排版 |
| 常规控件 | 34–36px 高；12–14px 界面文字；细线图标，无内层重复底色 |
| 普通字段网格 | 宽工作区 4 列，容器变窄后 2 列／1 列；长文本跨 2 列或整行 |
| 密度检查 | 标题、工具条、筛选、内容之间不再留下大段空白；少量资源也保持同样卡片尺寸 |

在主尺寸同时打开左右栏与资源列时，阅读区剩余约 596px；1366px 时约 506px。预览展示这个实际结果，保持用户可手动收起左栏的控制，不暗中放大整个页面或缩窄编辑栏。较窄窗口的资源列可收纳，不能用覆盖条目列表的浮层代替。

## 首页与五类常用资源

1. 世界书、连接、预设、用户设定：每次打开右栏时默认显示左侧一级资源列，搜索置于列顶；选中条目仍在原宽度的编辑区中编辑。资源列有独立收纳控件，右栏整体收纳是另一控件，名称和方向明确区分。
2. 世界书：圆形勾选只改变启用关系，点击名称只浏览条目；全局／当前角色作用域沿用已确认切换。一级资源、二级条目、正文编辑互不遮挡。正文编辑仍默认收纳，双击条目或点笔图标打开。
3. 角色：右栏“全部角色”的悬浮／键盘聚焦信息显示在同一 180px 左展列；移动鼠标到信息列时不闪退。悬浮不切换当前角色或聊天；点击选择才执行原动作。
4. 用户输入：折叠摘要与展开正文共用同一文本起点，箭头单独占固定小槽；展开时正文不偏移。动画只控制原节点外层的高度和透明度，不重复挂载正文或 iframe，快速连续切换从当前高度继续，减少动画偏好即时生效。
5. 预设：流式、思维链、参数收纳控件在同一行；固定字段另占紧凑行，无固定字段时不产生空行。提示词列表保留空间，编辑框默认收纳。
6. 保持输入底栏仅图标、阅读字体快捷控件、时间与楼层按偏好显示、头像和名称不进入消息正文。

## 低频设置迁移：保留组件关系，调整外观与容器

当前 `src/modules/DesignedSettings.tsx` 收集后代字段及按钮并将 `actions.map(renderAction)` 集中渲染；这无法正确表达嵌套列表、动态条目、局部标签页与作用范围。后续实现应停止对这些组件使用通用按钮收集器。

采用“整块原生组件挂载 + 工作台容器和样式”的方式：保留原节点、事件、字段显示条件和保存语义；选择稳定根节点挂载，卸载恢复原位置。复杂组件内部的树、列表、编辑器、文件操作和标签页由原组件管理。外观只在对应工作台根内覆盖，避免影响消息或插件 iframe。简单字段可按原分组排成四列，不能越过组件边界搬走局部操作。

| 页面／组件 | 保留的关系 | 外观迁移 |
|---|---|---|
| 回复格式 | 上下文／指令／系统提示词各自的模板选择与管理；停止串、推理模板、宏和适用条件 | 模板操作靠近模板选择；短选项四列，模板正文占整行；高级分组折叠，避免大空白 |
| 用户设置 | 原版主题、消息行为、角色群聊、脚本补全、账户等分组，以及即时保存语义 | 主题操作只在主题分组；普通选项四列、紧凑开关；颜色选择器整块保留；自定义 CSS 独占文本区 |
| 快捷回复 | 全局／当前聊天／当前角色的启用组关系；回复组管理；每条回复的标签、文本、触发及动作 | 作用域紧凑分组；组操作位于组选择旁；条目一行浏览、展开局部编辑，复制／移动／删除位于对应条目；不再陈列重复按钮 |
| 正则 | 全局／预设／当前角色集合、脚本顺序、启停、批量和预设管理 | 集合标题旁新建，条目操作留在条目，调试入口局部可达；保留原编辑器及应用规则 |
| 酒馆助手等第三方扩展 | 扩展自己的标签页、脚本／文件夹树、作用域、搜索与动态重绘 | 选择扩展后挂载其完整设置根，调整间距、输入样式和选中态；不枚举所有后代按钮，也不把组件状态转换为另一份表单 |
| Extras | 地址、凭据、连接状态、自动连接 | 一行紧凑连接区，凭据保持原处理；不制造多个空白栏目 |
| 背景 | 全局／聊天作用域、文件夹、图库、填充与自动选择、上传、批量、图片／视频及原操作语义 | 上方两条紧凑控制行；目录在侧、图库占主体；缩略图仅图片与简短名称，操作放悬浮／聚焦更多菜单；移动、从目录移除、删除文件明确区分 |
| 生成高级参数 | 后端适用采样分组、预设管理与提示词管理各自的位置和状态 | 资源操作回到资源表头；参数按组排列，适用字段四列，复杂控件保留整体 |

不是增加“进入原版”链接。所有现有功能在工作台内可达；未知第三方扩展优先保留其完整设置组件，后续遇到具体样式冲突再逐个适配。

## 接入顺序与验收

方案确认后，先修阅读展开和预设对齐，再做一级资源列及角色信息，再压缩角色／身份管理，最后按组件迁移低频页面。先保留原逻辑、核对功能位置，再美化；不改官方源码，不部署。

每页使用同一 CSS 工作区尺寸、栏宽、字体和数据量检查设计与运行时：主尺寸必须有左右栏、一级资源列、编辑默认收纳、展开正文、长名称、两条及多条角色、无条目等状态。检查悬浮／聚焦／勾选／下拉／快速连续折叠和减少动画。

验证不能只写“无溢出”：记录工具条高度、筛选行数、卡片宽高、四列数量、编辑栏宽度、一级列宽度及正文对齐。动态扩展还要验证新建／切换／删除后组件重绘、保存事件、局部动作目标和卸载恢复。方案预览里的交互只作用于示例，不代表原版功能已接入或全部通过。

本次方案预览完成 75 项局部交互与尺寸检查，记录在 `artifacts/migration-plan/verification.json`：主工作区 1496×817、顶栏 74、资源列 180、右编辑区 460、阅读区 596；展开输入与摘要标签的文本起点均为 x=326。角色卡 108px 高，筛选一行，普通字段四列；其余桌面尺寸及 1024／736／320px 对话预览容器检查通过，浏览器脚本错误为零。另对图库局部展开与独立预览尺寸复查，见 `focused-checks.json`。

低高度时，左栏信息可滚动而下方设置入口保留，阅读正文与输入区分开；独立页只滚动内容区，顶部与分类导航保留。图像导出倍率单独记录：`home-1496-2x.png` 为 2992×1634 图像像素，其 CSS 布局仍为 1496×817。不能用截图导出倍率去乘栏宽或字号。

可操作源为 `resource-migration.fragment.html`；`resource-migration.preview.html` 在真实浏览器内容区内按相同宽度规则显示。预览中字段及资源为示例，原版完整功能的接入范围以上面的本地源组件和现有资源编辑器为准。
