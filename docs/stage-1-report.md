## 2. 技术验证

`npm test` 的 7 项观察器测试、`npm run verify` 的 10 项浏览器验证全部通过。浏览器主流程没有新增未捕获 JS 异常。

| 能力 | 验证方式与结果 |
| --- | --- |
| 官方基线运行 | 干净实例加载至 `APP_READY`，使用原生生成 API 请求本地测试模型并获得回复 |
| 插件挂载 | 官方扩展加载后通过 `SillyTavern.getContext()` 接入；原生就绪后挂载独立探针，不占有消息或输入节点 |
| 可撤销回退 | 连续 5 次挂载／卸载，事件监听数量不增长；原 `#chat`、`#send_textarea` 节点、中文 Markdown/XML/宏草稿和选区保持一致 |
| 流式生成 | 通过原生发送按钮生成，SSE 被酒馆原有消费链路完整处理；观察器不读取响应正文 |
| 最终请求记录 | 记录浏览器实际发出的生成 POST，与组装事件关联；请求体保留消息顺序和参数 |
| 世界书命中 | 用关键字 `wb_lore` 触发合成世界书，收到原生 `WORLD_INFO_ACTIVATED`；实际请求包含对应内容 |
| 服务端出站验证 | 独立测试模型记录真正收到的 `/v1/chat/completions`；此 custom OpenAI-compatible 场景的 messages 与浏览器快照一致 |
| 非流式与取消 | 原生 `generateRaw()` 非流式回复正常；慢速 SSE 可由原生 stop 操作中止 |
| 酒馆助手 | 真正调用助手消息 API 生成 HTML iframe；按钮第一次点击与回退后的第二次点击分别改变 iframe 内状态 |
| 扩展停用 | 使用官方 disabledExtensions 机制停用探针，原生界面及酒馆助手继续加载 |
| 移动视口 | 390×844、触控模式下探针位于可视范围，按钮可以点击并恢复原生入口 |

测试使用合成角色、世界书与聊天，模型响应由隔离测试服务生成。没有读取生产聊天或调用真实模型。酒馆助手 iframe 本身引用外部 CDN；上述测试不构成离线可用性验证。

### 请求观察器的行为约束

- 仅观察同源、指定生成路径的 POST；不记录设置保存、认证头或其他普通请求。
- 原始参数、AbortSignal、Promise、Response 与流对象保持透传；观察失败不阻止请求。
- 不读响应正文，不缓冲 SSE，不将“收到 HTTP 响应头”描述成生成完成。
- 记录限于内存，最多 20 条；每个请求／事件正文快照有 128 KiB 上限，超限明确标记。
- 过滤 API key、认证字段、密码、自定义请求头以及 URL 内的凭据；正常模型参数如 `max_tokens` 保留。
- 卸载时移除监听并恢复自己的 fetch 包装；若其他插件随后叠加包装，避免覆盖它，并使保留的观察函数停止记录。

这是有可验证行为边界的最小探针，不包含正式 Trace 页面、持久化、跨请求树或全量后端观测。

## 3. 启动性能基线

同一验证服务、同一合成数据、1440×900 headless Chromium；每组 5 个新浏览器上下文，各自再导航一次形成热缓存样本。测试没有使用 Playwright 请求路由，以保留浏览器 HTTP 缓存。

| 启用组合 | 冷浏览器缓存 APP_READY 中位数 | 热浏览器缓存 APP_READY 中位数 |
| --- | ---: | ---: |
| 原生，禁用助手和探针 | 2.80 s | 2.31 s |
| 仅探针 | 2.55 s | 2.19 s |
| 酒馆助手 + 探针 | 2.76 s | 2.37 s |

“原生”对照仍发现两份已安装但禁用的扩展 manifest，它用于在同一实例内比较执行开销；另一个完全没有第三方扩展的官方基线实例已单独通过运行验证。

服务端重启到 HTTP 可响应的三次测量为 **19.47 / 5.34 / 5.61 s**，中位数 **5.61 s**。这包含 Docker 重启命令、退出／启动过程和约 100 ms 的轮询误差，属于已存在镜像和持久缓存下的重启数据，不能作为首次安装耗时或纯 Node 启动时间。

各组合样本范围有重叠，主机同时运行其他服务；仅探针中位数更低不能证明插件提速。当前证据仅支持：最小工作台接入可以运行，未出现明显且稳定的额外启动成本。生产角色卡规模、插件数量、长聊天及网络条件的开销尚未量化。

采样保留了导航、DOMContentLoaded、上下文可用、官方初始化／就绪、探针挂载、资源数量、传输字节和耗时最长的资源。资源请求并发执行，资源 duration 不能直接相加当作启动时间。

### 官方启动顺序带来的边界

官方代码显示，扩展加载发生在设置读取之后；普通前端扩展无法优化在自己执行前已完成的工作。官方在 APP_INITIALIZED 之后隐藏加载器，再发出 APP_READY。

因此后续优化先围绕测量结果处理模块加载、重复渲染和列表呈现。若生产测量证明早期设置、角色扫描或服务端步骤占主导，再单独设计可回退的增强方案。

已检查本机鸡尾酒及鸡尾酒+部署说明。鸡尾酒包含启动、聊天渲染、正则刷新三个模块；鸡尾酒+的 Early Bridge 方案会注入官方 index.html，不能直接视为严格零核心改动。本阶段没有加载这些优化器、启用后端增强或注册 Service Worker，避免污染官方对照。

## 4. 后续实现必须遵守的接入边界

| 边界 | 结论 |
| --- | --- |
| 数据 | 酒馆持有聊天、角色、预设、世界书；新 UI 不另建并行主数据源 |
| 状态与命令 | 业务模块通过适配层使用 `getContext()`，避免逐页直接导入内部模块 |
| 消息与输入 | 现有 `#chat`、`.mes`、`.mes_text`、`mesid` 与 `#send_textarea` 是插件兼容锚点；整体替换、虚拟化或移动节点前须再次验证助手 |
| 事件 Trace | `CHAT_COMPLETION_SETTINGS_READY` 可读取组装阶段参数；后续监听者仍可修改，实际 POST 才是浏览器请求的最终快照 |
| 世界书证据 | `WORLD_INFO_ACTIVATED` 给出已激活条目及内容；不包含所有未命中原因，且 dry-run 不发该事件 |
| 采集位置 | 明确区分 browser-to-SillyTavern 与 server-to-model；目前出站一致性只验证了合成 custom OpenAI-compatible 接口 |
| 模块清理 | 挂载、卸载、关闭与升级必须移除订阅、取消自己的异步任务，保留原生可用路径 |
| 移动浮层 | 酒馆移动样式对 html 设置 transform/perspective，html 高度可为 0；直接增加 fixed 浮层会产生错误的定位参照。探针使用酒馆全屏 body 作为绝对定位参照，并通过实际点击验证 |
| HTTP 标识生成 | 局域网 HTTP 不提供 `crypto.randomUUID()`；探针使用可在 HTTP 上运行的 getRandomValues 回退，正式 PWA 应使用 HTTPS |

官方允许扩展打包组件框架，但本阶段刻意保留最小原生探针，不提前选择或实现正式布局。生产中已存在的 `story-workspace` 部署资产说明使用 Vue、保留原生消息与输入节点；后续工作台阶段应先审阅其源项目，再决定与总体架构的整合方式。

## 5. 验收边界与下一阶段入口

第 1 阶段验收项已经完成：固定官方 release 与镜像、独立部署、源码完整性、挂载／回退、助手 iframe、轻量请求／命中证据、重复性能采样及复跑脚本。

后续独立验证项包括真实手机 PWA／软键盘、真实模型供应商差异、生产规模性能、其他第三方插件、文本补全后端与正式工作台布局。连接／预设／世界书编辑器、生图编排、导出与外部目录同步属于后续模块。

下一阶段先定位现有 `story-workspace` 源项目，形成公共设计系统与四场景布局原型，再按模块进行设计评审和开发。当前生产页面保持原部署。
