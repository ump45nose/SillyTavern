# 酒馆启动加载调查

2026-10-09。调查对象是打开／刷新网页至可用的时间，不是容器启动时间。

## 结果与测量边界

验证实例、同一浏览器会话中，启用工作台时酒馆约 2.8–3.0 秒就绪，工作台可见约 3.0–3.2 秒；就绪后挂载约 0.16–0.29 秒。此处没有复现用户实际浏览器的极长等待，不能推断其原因已经解决。

| 浏览器内配置 | 导航 | 酒馆 APP_READY | 工作台可见 | 首字节 |
| --- | --- | ---: | ---: | ---: |
| 工作台开启 | 新会话首次打开 | 2.95 s | 3.24 s | 11.4 ms |
| 工作台开启 | 同会话刷新 | 2.83 s | 2.99 s | 10.5 ms |
| 仅本会话停用工作台 | 新会话首次打开 | 3.26 s | — | 9.4 ms |
| 仅本会话停用工作台 | 同会话刷新 | 5.52 s | — | 20.5 ms |

每项为一次样本，数据为 3 个角色、1 条当前聊天，酒馆助手保持启用，1496×817 CSS 视口。停用工作台的刷新样本里，多项原生库请求约 1.8 秒，体现了请求等待波动；不能用该单次差异宣称工作台提速。其他样本最长请求包含助手的 GitLab 版本检查和外部 Vue 资源，也不能仅凭资源耗时认定其阻塞了初始化。

`npm run benchmark:startup` 保留浏览器 HTTP 缓存，仅在浏览器 fetch 层阻止设置和聊天写入；不使用 Playwright 请求路由，因为路由会禁用 HTTP 缓存。角色、身份、聊天及服务配置未被修改。完整采样见忽略入库的 `artifacts/startup-readonly-benchmark.json`。以上测量在远程开发主机的 Chromium 上完成，不代表用户客户端的网络、缓存、插件规模或真实聊天负载。

## 当前运行时的等待链路

固定的 SillyTavern 1.19.0 初始化依次等待版本／密钥／语言、扩展与设置、头像、角色列表、背景、分词器、身份、脚本补全和抓取器，最后完成初始化、解除加载遮罩并触发 APP_READY。扩展按顺序等待脚本、样式及激活钩子。源码依据：`upstream/SillyTavern/public/script.js` 及 `public/scripts/extensions.js`；对应固定 release 为 [官方 1.19.0](https://github.com/SillyTavern/SillyTavern/releases/tag/1.19.0)。

工作台加载顺序为 1000，在 APP_READY 后挂载；普通前端扩展无法消除自己执行之前的网络和原生初始化等待。现有资源编辑器按需加载，本次的常用工具设置、加载诊断、记录导出和 XML Worker 同样按需加载。没有修改核心启动链路或安装优化器。

实际定位应区分：

- 首字节等待：访问网络或服务响应。
- 页面／脚本资源下载：缓存、外部 CDN、网络与资源数量。
- 脚本执行及扩展激活：主线程长任务、扩展依赖和初始化钩子。
- 头像、角色、背景等 API 等待：数据规模与服务端读取。
- APP_READY 后工作台挂载：布局、订阅及首轮渲染。

## 已核对的处理方案

「鸡尾酒」前端启动模块在 SETTINGS_LOADED 后预取头像、角色和背景，并包装 fetch 复用结果，同时尝试提前解除遮罩。该方案主要覆盖后半段接口等待；提前露出页面不等于完成初始化。[模块源码](https://github.com/Lianues/cocktail/blob/main/modules/startup-optimizer.js)

当前 1.19.0 虽保留已弃用的 `context.hideLoader()`，但其操作 legacy loader；原生启动使用独立的 `loader.show()` 句柄。因此不能假定旧式 hideLoader 一定能解除当前启动遮罩，需专门验证版本兼容性。[官方 loader 实现](https://github.com/SillyTavern/SillyTavern/blob/1.19.0/public/scripts/loader.js)

「cocktail-plus」的当前方案涉及浅层角色缓存、Service Worker、后端快速接口与 Early Bridge。官方说明指出后端会向原生 index.html 插入桥接脚本；服务端入口还包含按配置执行源码补丁的逻辑。[方案说明](https://github.com/Lianues/cocktail-plus/blob/main/README.md)、[服务端入口](https://github.com/Lianues/cocktail-plus/blob/main/server-plugins/cocktail-plus/src/index.ts)

这些方案本次仅调查，未安装。应先在用户实际等待阶段取得证据：如果主要耗时来自角色 API，再评估兼容缓存；如果主要是资源和外部网络，再检查缓存及依赖交付；如果主要是扩展钩子，再逐项测量。不要同时叠加多个 fetch／保存拦截器，也不要先改核心再寻找原因。

## 可直接使用的诊断页

用户设置 → 加载诊断，记录本标签页最近五次导航，提供首字节、页面结构、工作台脚本、酒馆就绪和工作台可见时间，列出已完成的慢请求和捕获到的主线程长任务。时间线是从导航开始的累计时间，不能相加。

采集通过 Navigation／Resource Timing、PerformanceObserver 和原生事件完成，不包装 fetch、不读取响应正文，不改变加载遮罩或初始化事件。报告包含耗时、资源路径和数量，不包含密钥或聊天正文，可直接下载 JSON。

诊断在扩展引导代码执行时才开始扩容资源缓冲；早期默认 250 项缓冲可能已经满，页面会明确标示资源列表不完整。部分外部资源不给出传输大小，不能误判为缓存命中。浏览器不支持长任务指标时保留其他数据。
