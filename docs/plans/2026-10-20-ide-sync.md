## 关键决定

- **文件名用界面用词**：与界面不一致时以界面为准，例如 `角色描述.md`、`第一条消息.md`、`对话示例.md`、`创作者注释.md`、「发言积极性」、「辅助关键词」。
- **标题即文件名**：条目标题、提示词名称、连接名、用户设定名取自文件名；文件名无法原样表达（空、含 `/` 等、重名）时，frontmatter 写出「标题 / 名称」并给文件名加区分后缀。改名用 VS Code 的重命名。
- **身份在 frontmatter**：条目靠 `uid`、提示词靠 `identifier` 定位。新建条目 / 开场白时新建文件、不写 uid；`uid` 已属于另一个文件时拒绝写入，不会把复制出来的文件当成改名。
- **没写出的字段保持原值**：文件只覆盖它表达的字段，ST 的其余字段（displayIndex、匹配范围开关、extensions 等）从当前数据原样保留，所以往返恒等，也不会丢插件数据。
- **版本号 = `<mtime>:<hash>`**：hash 是该虚拟文件文本的 sha1。mtime 按虚拟文件计：文本不变则 mtime 不变，变了取 `max(now, 上次+1)`，避免同一世界书里改 A 条目让 B 条目也被 VS Code 判为「磁盘上已更改」。PUT 比较基准 hash，不同返回 409。
- **写入路由**：该用户有已连接的工作台页面时一律先交给页面（`{kind, id, base, draft}`，10 秒超时）；页面回 `skip`（大纲 / 数据库所在聊天没打开）时，大纲改为直写磁盘，数据库返回「打开该聊天后可同步」。没有页面时直写磁盘。
- **页面草稿不覆盖**：中转写入不碰页面里的草稿；编辑器有未保存修改时不重新载入，之后保存仍按 base/draft 三方合并（页面改过的字段以页面为准）。正在使用的预设：只把页面运行值与原文件一致的字段同步进运行设置，其余字段记为冲突显示在状态卡里。编辑页内逐字段的冲突提示属于其他会话正在改的文件，本次不做，由状态卡列出。
- **服务端引用 ST 模块**：插件经符号链接加载，`import.meta.url` 指向本仓库，所以按 `process.argv[1]`（server.js）定位 ST 根目录，再动态导入 `src/character-card-parser.js`、`src/util.js`。
- **访问令牌**：`config.yaml` 里 `workbenchSync.token`（或环境变量 `SILLYTAVERN_WORKBENCHSYNC_TOKEN`）非空时，IDE 端接口要求请求头 `X-Workbench-Sync-Token`。页面端接口只靠 ST 自身会话认证。
- **监视按需开启**：某用户有 IDE 订阅时才对其目录开 `fs.watch`，最后一个订阅断开即关闭；每个源文件 150 ms 去抖。
- **依赖**：`yaml`（打包进插件和 VS Code 扩展，页面不引入）；开发依赖 `@types/node`、`@types/vscode`。.vsix 用现有的 fflate 自行打包，不引入 vsce。

## 公网说明（未验证）
