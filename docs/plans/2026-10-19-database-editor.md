# 数据库插件入口与表格编辑页（2026-10-19）

分支 `claude/database-plugin-entry-control-2a026b`（基于 workbench f943fd9）。对接的插件是「龙血玄黄·数据库」（AlbusKen/shujuku），全局对象 `window.AutoCardUpdaterAPI`，接口以它的 `API_DOCUMENTATION.md` 和源码为准。

## 权衡：右边栏还是独立设置页

数据库存的是本聊天的故事状态，每轮回复后由插件自动填写。最常见的操作是：读完一轮，对照正文看一眼人物、物品、任务，改掉一两个填错的格子，或者锁住不想让 AI 再动的事实。

- **右边栏**：在正文旁边，能对照着改。插件的表普遍有 5–12 列，摘要类的格子很长，460px 宽放不下表格。
- **独立设置页**：放得下整张表，适合通览、比较多行、按列锁定。缺点是盖住正文，没法边读边改。而且设置工作区放的是酒馆的配置，数据库是聊天里的数据。

**决定：沿用世界书的两级入口。**
- 主要编辑放在右边栏，按窄栏来设计：一行是一条记录，编辑时把各列竖排成表单，不用表格。
- 栏头的「独立深度编辑」打开设置工作区的「数据库」页，这里是完整的表格：通览、按列锁定、展开行就地编辑。
- 两处共用同一个运行时和同一个行编辑器。
- 插件自己的配置（API、提示词、模板结构、更新频率）不重复做，「数据库设置」按钮打开插件自己的界面。

## 入口

只在检测到插件时出现，没装插件就不显示任何入口。
- **右栏标签「数据库」**：放在「大纲」之后，和大纲同属故事状态。表格列表放在资源轨里。
- **输入框工具「数据库」**：在阅读或 RP 中一键打开或收起数据库栏。插件填表期间，图标上有呼吸点。
- **设置工作区「数据库」页**：作为深度编辑。

## 编辑页设计

**右栏**
- 资源轨：
  - 顶部是状态卡：「填表中」或「每 N 层自动填表」，下面是「立即填表」和「数据库设置」两个按钮；
  - 下面是表格列表，显示表名和行数，有锁定的表带锁标记。
- 表头：表名，以及「N 行 · M 列 · 锁定 K」，加「新增行」按钮。表说明（`sourceData.note`）默认只显示一行，点开看全文。
- 行列表：
  - 每行显示序号、标题（第一个有内容的列）和摘要（第二个有内容的列）；锁定的行带锁标记；
  - 行数超过 6 时显示搜索框，按所有格子过滤；
  - 只有一行的表不显示列表，直接显示表单。
- 行编辑卡：
  - 列名在上，自适应高度的文本框在下；
  - 每个字段都有锁定开关（单元格锁）。被锁住的字段只读，并说明是被哪一级锁住的（行、列、单元格）；
  - 卡头有整行锁定和删除，删除要在原位二次确认；
  - 改动先进草稿，只在有改动时出现保存条，支持 ⌘S。离开或切换行时有守卫。
- 新增行：先打开一张空表单，保存后才调用 `insertRow`。

**深度页（设置工作区）**
- 左列：当前聊天名、状态卡、表格列表。
- 主区：
  - 表名，徽标显示行数和锁定数；
  - 表格：表头粘顶，左侧固定一列放序号和行锁；内容长的列自动加宽，格子最多显示两行；
  - 表头上的锁切换整列锁定；
  - 点一行，在它下方展开同一个行编辑器，字段排成两栏，长文本占整行。

## 写入语义

- 保存只提交改过的列：`updateRow(表名, 行号, {列名: 值})`。行号在保存时按 row_id 重新查找，避免插件期间填表导致行号错位。
- 插件对锁定目标会拒绝写入，返回 false 但不给原因。界面提前把锁定字段设为只读；写入被拒时说明可能的原因。
- 锁定用 `toggleTableRowLock / ColLock / CellLock`。这三个接口的下标是从 0 开始的数据位置，`updateRow` 的行号从 1 开始，两套下标在运行时里换算。
- 回调：
  - 表格更新回调和填表开始回调都通过一个页面级的固定函数注册（插件按函数身份去重），重复挂载不会累积；
  - 更新回调在卸载时注销。填表开始回调插件没有注销接口，卸载后转发为空。
- 剧情选项的「数据库表」来源改为读这个运行时，不再单独订阅插件。

- 单元测试 `tests/database.test.mjs`：读取导出（排序、row_id 列、说明、单元格转字符串）、标题与摘要、过滤、锁定判断、改动列计算。
- `verify:database`（页面内模拟插件，按插件语义实现增删改、锁定拒写和回调）：
  - 没有插件时不出现任何入口；有插件时入口出现；
  - 右栏：切换表、编辑并保存、改动只提交改过的列、新增、删除确认、单元格锁和行锁变为只读、填表状态、单行表直接显示表单；

  - 手机端：右栏标签和表格切换。
- 回归：verify:rp（剧情选项的数据库来源）、verify:pwa、verify:interactions（工具数量）、全量单元测试和门禁。

## 真实插件联调（2026-10-19）

插件取自 AlbusKen/shujuku main@df3f562af4d5（「龙血玄黄·数据库 1.3」）。按提交 tarball 解压到 32012、32014 两个实例的 `data/default-user/extensions/shujuku`，不进仓库。

- **默认关闭插件。** 插件每层回复后会自动填表并注入提示词，因此验证会话（`session()`）默认把插件的 `index.js` 换成空模块，只有传入 `database: true` 才加载。
  - 用替换文件而不改设置，是因为有的验证会自己拦截 `/api/settings`（例如 writing-addons），设置注入会被它覆盖，插件照样加载。
  - 这样也不写账号设置。
  - verify:database 继续用模拟插件。
  - `reset-visual` 保留手动安装的扩展。
- **`verify:database-real`：** 没装插件时跳过。脚本只写 WorkbenchFixture 聊天，写入的行会删掉。实测通过：
  - 插件在聊天打开后才异步载入表格，工作台通过更新回调拿到 9 张表；列不含 row_id；
  - 新增返回 row_id；保存只提交改过的列；
  - 行、列、单元格锁的下标从 0 开始，与设计一致，插件拒绝写入被锁的目标；
  - 删除生效，每次写入都触发更新回调；
  - 剧情选项跟随真实选项表变化；
  - 「立即填表」：状态先是填表中，结束后清除（模拟模型约 10 秒）；
  - 右栏和深度页能显示真实表格，没有页面错误。
- **回归：** 改为替换文件后，database、writing-addons、database-real 通过，pwa 连续 3 次通过。

    - 一次是挪走插件后的另一处断言。
  - 原因没有定位，按偶发记录。
