## 现状证据

代码（workbench b13cb93）：

- 连接已有分组：`prefs.groups[profileId]` 自由文本，`ResourcePicker` 的 `grouped` 模式按它分组（`Resources.tsx` 编辑分组名）。世界书没有分组，没有任何资源有归档。
- 世界书列表 = `getWorldInfoNames()` 全量；边栏、顶栏下拉（`ResourcePicker`）、独立编辑页（`ResourceManager` + `World` 书列）、手机（`MobileShell`）各自渲染同一份 `snap.resources.world`。
- 全项目没有列表虚拟化：深度编辑的条目表、边栏条目、角色、楼层、资源列表都是全量 DOM。
- 深度编辑的选中条目以内联行展开在表格中间（`World.tsx` `{entry === id && editor}`），编辑器高度占满视口，下方条目被推出屏幕，即截图中的遮挡问题；内联展开也与虚拟化不兼容。
- 深度编辑对整本书所有条目做 token 计数（`useTokenCounts`）。
- `SETTINGS_UPDATED` 让 session / characters / resources / prefs 全部失效，所有订阅 `withoutChat` 的面板随每次设置保存重渲染。

生产数据（fn `default-user`，只读统计）：

- 世界书 64 本 / 6028 条 / 34 MB；最大一本 `X-性癖大世界2.1` 9.2 MB、3189 条。角色 10 张、聊天 1 个——"角色卡/聊天较多"在生产上没有复现，需要用合成数据覆盖。
- **`settings.json` 8 MB**：`extension_settings` 340 万字符，其中 `vectors_enhanced` 122 万（扩展已停用）、`tavern_helper` 115 万、`__userscripts` 52 万、`TavernHelper` 29 万；`oai_settings` 192 万。酒馆每次保存设置都整份上传、每次启动整份下载。已停用/已删除扩展遗留键不少（vectors_enhanced、LittleWhiteBox、st_bme、story_workspace、ai_worldbook_router 等）。
- 仍启用的第三方：Response-Linter、Extension-MessageLimit、cocktail、Dialogue-Colorizer、JS-Slash-Runner 等，它们与工作台叠加的开销需要和原生基线分开测量。

### W1 性能

先测后改，以证据定优先级：

1. **测量**：本地验证实例导入生产数据副本（世界书 + settings.json，只读拷贝），另加合成规模数据（约 1000 角色、单角色 200 个聊天文件）。分别测原生基线与工作台：启动、打开 3189 条世界书、条目按键、设置保存一次的耗时与请求体大小。扩展 `benchmark-hotpaths` / `benchmark-startup-readonly`。
2. **预计改动**（按测量结果取舍）：
   - 条目表、边栏条目、角色列表、楼层列表虚拟化（一个共用的定高窗口化组件，不引第三方库）。
   - token 计数只算可见条目 + 已编辑条目，整本合计改为按需或后台分批。
   - `SETTINGS_UPDATED` 的失效收窄：只失效确有变化的分片（比较连接、预设、世界书选择等指纹），不再每次全量重建角色列表。
   - 工作台自身的偏好写入合并防抖，避免一次交互触发多次 8 MB 保存。
3. **settings.json 瘦身**（生产数据操作，已同意，见关键决定 4）：备份后删除已卸载/已停用扩展的遗留键并重启容器；`tavern_helper` / `__userscripts` / `oai_settings` 为在用数据，只报告不动。
4. 路线图备选池里的渲染手法（分帧加载、iframe 渲染缓存等）按测量结果挑选，不预先实现。

### W2 条目详情布局

深度编辑改为主从布局：条目表保持可见，选中条目在右侧固定详情栏编辑（独立滚动），详情打开时表格收起次要列（触发关键词、位置等）；窄窗口/手机用覆盖层。选中行常驻高亮，上下键切换条目。与 W1 条目表虚拟化同一次改。

### W3 分组与归档（主体）

**数据**：沿用 `extensionSettings.workbench`（与现有连接分组同处），新增世界书分组映射与两类资源的归档集合；世界书以名称为键，加载时清理已不存在的键，工作台内删除/改名同步更新。字段在详细设计中定。

**界面**：

- 边栏（资源 rail）：世界书按分组折叠显示，未分组置底；归档项不显示，底部一行「已归档 N」可展开。组头带组级启停（一键启用/停用整组），即路线图 P2「世界书快捷切换」，并入本项。

- 独立编辑页：分组管理（新建、改名、删除、批量移入分组），批量归档/恢复（复用现有多选与批量栏），列表顶部「全部 / 已归档」切换。
- 手机 `MobileShell` 同步上述规则。

涉及 `host/core`（偏好与资源构建）、`ResourcePicker`（四类资源共用）、`Resources`、`ResourceManager`、`World` 书列、`Header`「下一个」、`MobileShell`、快捷键，以及相应 verify 脚本——这是本轮改动面最大的一项。

### W5 占位符变量

来源：酒馆助手脚本「占位符系统 v4.5.0」（生产 settings 中 tavern_helper 脚本 #3，已停用，约 2 万字符）。真实使用者：快速回复集「👑超级菜单」35 条中有 22 条用到它，例如控制菜单 `{@女主:女主:请输入接下来剧情女性的名称:-1}` 弹窗设定名字，其余条目用 `{@女主:女主}` 读取。脚本停用后这套快速回复无法正常工作。

原脚本行为：

- 语法 `{@变量}`、`{@变量:默认值}`、`{@变量:默认值:提示语}`（弹窗输入）、`{@变量:默认值:提示语:指示数}`（指示数 ±1/2 控制弹窗与替换）、`{@变量=值}`、`{@变量!}`，以及 `{@list}`、`{@clear}`、`{@reset}`、`{@input:toggle}` 等命令。
- 输入框出现 `{@` 时防抖 600 ms，就地展开成文本；Tab 立即展开；包装 `/inject` 命令，让快速回复里的 `/inject {@变量}` 也能展开。
- 变量按角色卡分组存在浏览器 localStorage（换设备、换浏览器即丢失）；带变量列表和编辑弹窗。
- 另带一段快速回复工具栏样式（分隔按钮 `--------` 之前的按钮变成吸顶工具栏）。

工作台实现：

- **语法与指示数语义完全兼容**，超级菜单无需改写。展开逻辑写成纯函数，用单元测试覆盖原脚本的各种格式。
- 变量仍**按角色卡**分组，改存工作台设置，跨设备同步；旧 localStorage 数据不迁移（值都是名字，弹窗会重新询问）。
- 展开入口：原生输入框（工作台保留原生 `#send_textarea`，就地展开，任何发送路径都覆盖）和 `/inject` 命令包装；弹窗用工作台对话框。
- 变量管理放进右栏或用户设置：查看、编辑、删除当前角色的变量。
- 快速回复工具栏样式：先核对工作台输入框底栏的快速回复呈现是否需要，需要再做。

复杂度中：语法解析简单，风险集中在包装斜杠命令与输入框时序（输入法组合输入、流式生成中、快速回复自动发送）。

### W6 说话人着色

来源：Dialogue-Colorizer（生产上仍启用；它依赖的 `Vibrant.min.js` 是 0 字节，从头像自动取色已失效）。实际生效的配置只有两个 persona 的手动颜色，角色侧没有设置任何颜色。

工作台实现：按消息作者给引号对白上色（原生把对白渲染为 `<q>`），颜色来源为手动指定的角色 / persona 颜色，可选从头像取主色（canvas 自取，不引第三方库），颜色按当前主题做对比度修正；生成一张样式表，不改消息 DOM。Noval 阅读区与 RP 舞台都要覆盖。迁移那两个 persona 的颜色，上线后在生产上停用 Dialogue-Colorizer。复杂度低。

## 关键决定（2026-10-25 确认）

1. **归档只隐藏**：工作台设置里的元数据标记，文件不动；归档项不出现在边栏、顶栏下拉、「下一个」与快捷键中，独立编辑页可恢复。不做物理移动，不需要服务端插件。
2. **在用的不能归档**：世界书全局启用、或绑定在角色卡 / 当前聊天 / 人设上时，归档按钮禁用并说明原因；连接同理，当前连接不能归档。归档不自动改任何启用或绑定状态。
3. **分组单层，一本书只属一个组**，与现有连接分组同一形态；组头提供整组启停。
4. **settings.json 瘦身**：M0 执行，备份 → 删除停用/卸载扩展的遗留键 → 重启容器；执行前列出键名与大小过目，不做前后计时。
5. 路线图 P1 两项（世界书路由、回复格式修复）本轮不做，另行立项；P3 骰子控件为错误需求，取消。
6. 备选池的占位符变量与说话人着色纳入本轮（W5、W6）；占位符保持原语法兼容，变量按角色卡分组并改存工作台设置。
